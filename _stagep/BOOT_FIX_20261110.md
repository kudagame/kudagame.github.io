# 寵物測試頁空白啟動修復（第一輪歷史記錄）

**後續實測找到圖片timeout造成永久空白的問題；8秒載入策略已由第二輪取代。請以 BOOT_FIX2_20261110.md 為準。**

## 證據與根因

- 原始碼：`P.boot()` 先 `P.load(); P.open()`，然後 `await P.art.load()`，全部完成後才 `P.go('shelter')`、啟動 RAF。原本 `loadSet()` 對十種動物逐一先等 `../chars/pets/.../out/anchors.json`，之後才讀已經存在的本頁 manifest。
- **404 / 503 的 `!ok` 已有處理**，立即失敗時會正確回到 packed；不是把 503 當有效 JSON 的 bug。Node 重現原版回傳 503：10 個外部請求、booted=1、院子繪製7次、沒有缺圖或 JS error。
- **沒完成的請求沒有 timeout**；任何一個慢／懸掛的開發來源請求都會擋住整個畫面及按鈕。Node 將第一個 fetch 保持 pending：ready=false、沒有 scene、按鈕列空、0 次繪製；存檔已建立但0隻寵物，符合所述空畫布／DEV還能開的症狀。
- 已移除的 staging 快照無法再核對。現在完整源碼一次 boot 只會查10個 anchors，不是約90個；所以無法斷言先前90個究竟來自幾次啟動、過程中拷貝不完整或其他版本。不能把「立即503本身一定導致永遠空白」當成結論。可確認並已消除的是啟動必經的跨目錄、無時限、串行開發資產探測。
- P5.3 現有清單及混種檔案完整；完整HTML腳本順序啟動沒有 JS error、沒有缺圖。fresh save 本來就0隻，必須先看見院子及「救援任務：蜜糖之家保衛戰」入口；r1沒有完成前不應自動送寵物。沒有改任務獎勵／限領邏輯。

## 修補

1. 發布用 art loader 只讀 `assets/pets/` 下的 packed manifest與圖紙；移除 `../chars` 網路探測，不再依賴本機開發目錄。
2. 圖片載入各自有8秒上限，失敗記入 `P.art.missing`，不會無限等候；一般缺圖顯示通知。西施基礎清單缺失則顯示明確錯誤。
3. HTML 有初始讀取提示；boot例外會顯示原因和44px觸控重試按鈕，避免只剩空畫布。p51 wrapper不再於失敗後繼續正常初始化。
4. 手機：移除html/body的全域 `touch-action:none`（它會禁止子面板捲動）；僅canvas／搖桿禁瀏覽器手勢，按鈕列可水平捲、面板可垂直捲。橫向按鈕維持至少44px，加入底部safe-area。
